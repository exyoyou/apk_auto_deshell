## 一句话全景

易盾有 **4 层防御**,打法是 **4 把钥匙**:

| # | 防御层 | 破法 |
|---|---|---|
| ① | APK 完整性校验(改字节就 `exit(28)`) | **不改 APK**,用 Zygisk 注入 gadget |
| ② | libvuoum 运行期反 frida(inline-svc 自杀 `exit(28)`) | 内存里 **NOP 两个自杀 svc 点** |
| ③ | `:mind` 守护进程跨进程 `kill(主pid, 9)` | **双 target** 把 :mind 一起 patch |
| ④ | 主体 DEX 抹掉 `dex\n` 头 + CodeItem 加密 | 内存里 **整体解密后**扫 rw-anon 区 dump |

脱壳拿到 DEX 后,重打包只需:**换掉壳 Application 入口 → 塞回真 DEX → 重签名**。

## 第一阶段:过 frida 检测(让 frida 能常驻且 app 不死)

### 关键认知(踩过的坑)

1. **绝不能用 apktool 重打包后再注入**。易盾有 native 文件完整性校验:任何改动 base.apk 字节 → `exit(28)`(纯 d→b→resign 零修改也秒退)。签名伪造只骗过 Java 层签名校验,骗不过 native 完整性校验。
   → **只能用 Zygisk 注入 gadget**(APK 保持原样,zygote fork 后注入 .so)。

2. **告密点不是 frida 足迹,而是多层**:时序、经 inline-svc 读 /proc/maps、内存里的 frida/gum 明文字符串、代码字节特征/linker soinfo。单纯清字符串/改名 gadget/remap 匿名**都不够**。
   → 真正有效的是:**直接 NOP 掉 libvuoum 的自杀 svc**,让它检测到也杀不了自己。

3. **frida-server / ptrace attach 会被检测**(:mind 读 TracerPid → kill 主进程)。只能用 **gadget(无 ptrace)**。

### 1.1 定位 libvuoum 的自杀点(动态 dump + capstone)

libvuoum.so 自身加壳(伪造段名 `.gnu.fragment` 熵 8.0 加密),**运行时原地自解密**。root 读内存不触发检测:

```bash
PID=$(adb shell pidof com.join.android.app.mgsim.wufun | tr -d '\r')
BASE=$(adb shell su -c "cat /proc/$PID/maps" | grep libvuoum | grep 'r-xp 00000000' | head -1 | cut -d- -f1)
# dd 出运行时 r-x 段(off 0, 0xbc000)→ 得明文代码 → overlay 回文件重建可分析 so → capstone 扫 svc
```

**本次定位到的自杀点(libvuoum 内偏移,换设备/版本需重定位)**:
- `0x27bd4` = `svc` x8=94(**exit_group**)
- `0x27c34` = `svc` x8=129(**kill**)

### 1.2 ZygiskFrida 双 target 配置

`/data/local/tmp/re.zyg.fri/config.json`(**主进程 + :mind 守护进程都要注入+patch**):

```json
{ "targets": [
  { "app_name": "com.join.android.app.mgsim.wufun",      "enabled": true, "start_up_delay_ms": 3000,
    "injected_libraries": [ { "path": "/data/local/tmp/re.zyg.fri/libgadget.so" } ] },
  { "app_name": "com.join.android.app.mgsim.wufun:mind", "enabled": true, "start_up_delay_ms": 500,
    "injected_libraries": [ { "path": "/data/local/tmp/re.zyg.fri/libgadget.so" } ] }
] }
```

`libgadget.config.so`(gadget 用 **script 模式** 跑我们的脚本,不用 listen):
```json
{ "interaction": { "type": "script", "path": "/data/local/tmp/re.zyg.fri/config.json.example", "on_change": "ignore" } }
```
脚本放在 `config.json.example`(覆盖已有文件)。

### 1.3 反自杀 + 反 kill 脚本(gadget on_load)

```js
// ① NOP libvuoum 自杀点
var m = Process.findModuleByName('libvuoum.so');
if (m) { var nop=[0x1f,0x20,0x03,0xd5];
  [0x27bd4,0x27c34].forEach(o=>{ var a=m.base.add(o); Memory.protect(a,16,'rwx'); a.writeByteArray(nop); }); }
// ② 拦 kill/tgkill/tkill 的致命信号(:mind → 主进程 signal 9/6/15)
[['kill',1],['tgkill',2],['tkill',1]].forEach(p=>{ var e=Module.findExportByName(null,p[0]);
  if(e) Interceptor.attach(e,{onEnter:a=>{ var s=a[p[1]].toInt32(); if(s===9||s===6||s===15) a[p[1]]=ptr(0); }}); });
```

**结果**:exit(28) 用 NOP 破,signal(9) 靠同时 patch :mind 破 → 主进程稳定 70s+,app 业务逻辑正常跑,frida 常驻。

## 第二阶段:导出完整 DEX

### 关键认知

- 易盾这个 build 是**加载时整体解密整个 dex**(不是逐方法抽取),所以内存里的 dex 100% 已解密。
- 隐藏手法:**删掉每个 dex 开头 4 字节 `dex\n` magic**,让扫 magic 的工具失效。
- **字符串是明文**(别被「搜不到类名」误导,是搜错子串/时机)。

### 2.1 ❌ 旧方法(FART / hook DoCall)不完整

hook `DoCall` + `GetCodeItem` 只能发现**被解释器执行过**的方法所在 dex 区 → 只抓到 **4 dex / 29779 类**,**入口类和约 89% 组件全缺**(走 Nterp/已编译/没点到的界面抓不到)。

### 2.2 ✅ 正确方法:扫全部 rw 匿名区

不依赖执行,直接扫内存里所有 rw 匿名区,凡是 dex 结构就 dump(`scripts/unpack_netease/maps_dump.js`,保留第一阶段的反自杀 patch):

```js
// 被抹头后:区首 4 字节 = "035\0" = 30 33 35 00;偏移整体 -4,所以
// header_size@(raw 0x20)==0x70、endian_tag@(raw 0x24)==0x12345678、file_size@(raw 0x1c)
Process.enumerateRanges('rw-').forEach(r => {
  if (r.file) return;
  const h = new Uint8Array(r.base.readByteArray(0x28));
  if (!(h[0]==0x30 && h[1]==0x33 && h[2]==0x35 && h[3]==0x00)) return;
  if ((h[0x20]|h[0x21]<<8|h[0x22]<<16|h[0x23]<<24) !== 0x70) return;
  if (!(h[0x24]==0x78 && h[0x25]==0x56 && h[0x26]==0x34 && h[0x27]==0x12)) return;
  // dump 整段到 /data/data/<pkg>/zf_mdex_N.bin
});
// setTimeout 多轮(5s/10s/16s…)兼顾懒加载;本例首轮(5s)就抓齐,后续 0 新增
```

跑法:杀透 app(含 :mind)→ 启动 → 等 ~12s → 拉文件:
```bash
for n in $(seq 1 10); do adb shell su -c "cat /data/data/$PKG/zf_mdex_$n.bin" > zf_mdex_$n.bin; done
# 校验:每个文件头 4 字节应为 30 33 35 00
```

**结果**:**10 个 dex / 72474 class_def / 覆盖 manifest 1247 组件中的 1229 个**(缺的 18 个是 Overmind VA 框架桩 `com/xinzhu/overmind/*`、按需 Arena 插件 dex、`default/alias`,不影响主流程)。

### 2.3 重建为合法 DEX

`scripts/unpack_netease/rebuild_dex.py`:
```python
dex = b"dex\n" + raw                               # 补回被删的 magic
body = bytearray(dex[: struct.unpack_from('<I',dex,0x20)[0]])   # 截到 file_size@0x20
body[0x0c:0x20] = hashlib.sha1(bytes(body[0x20:])).digest()     # 重算 signature@0x0c
struct.pack_into('<I', body, 0x08, zlib.adler32(bytes(body[0x0c:]))&0xffffffff)  # 重算 checksum@0x08
```
验证:`dexdump -f classes_main_N.dex`;快速枚举类(不反汇编):`scripts/unpack_netease/list_classdefs.py`。

## 第三阶段:生成可安装的脱壳 APK

### 关键认知:找对真正的 Application 入口(最大的坑)

壳把 manifest 的 `application android:name` 改成了桩 `com.vuaukou.vco.hykiiuy.MyApplication`。
真正的 Application **不是中间类 VApp,而是继承链最末端的 `com.MApplication`**(包名就叫 `com`):

```
com.MApplication            ← 真入口(Hilt 叶子,持全局静态 z = app context)
  └ com.Hilt_MApplication
      └ com.join.kotlin.base.BaseApp
          └ com.join.mgps.va.overmind.VApp
              └ com.papa91.arc.MApplication
                  └ com.papa91.arc.BuglyApplication
                      └ android.app.Application
```

- `com.MApplication.onCreate` 里 `f2958z = this`(全局静态 context `MApplication.z`)。
- 设错入口(如 VApp)→ `com.MApplication` 从不实例化 → `z` 为 null → ORMLite `getHelper(null)` → `IllegalArgumentException: context argument is null`,主界面出来后约 7s 崩。
- 真 launcher 是 `default.alias → MGMainActivity_`(`SplashActivity_` 未 exported,仅内部用)。
- **找真入口通法**:枚举继承到 `android/app/Application` 且无子类的「叶子 Application」,或 grep 壳 dex 里被引用最多的 `*Application` 类名。

### 重打包步骤

```bash
A=~/.apklab/apktool_3.0.3.jar
# 1) 解包(-s 保留原 dex、不反编 smali,避免重编译且不碰资源逻辑)
java -jar $A d -s -f test_papa.apk -o work
# 2) 改入口 Application 为真类
sed -i 's#android:name="com.vuaukou.vco.hykiiuy.MyApplication"#android:name="com.MApplication"#' work/AndroidManifest.xml
# 3) 重建(aapt2 重打资源+manifest,原 dex 原样带入)
java -jar $A b work -o unsigned.apk
# 4) 抽掉壳 classes.dex(81MB),塞 10 个真 dex(ART 原生 multidex 全加载)
cp classes_main_1.dex stage/classes.dex
for n in $(seq 2 10); do cp classes_main_$n.dex stage/classes$n.dex; done
(cd stage && zip -d ../unsigned.apk classes.dex && zip -X ../unsigned.apk classes.dex classes{2..10}.dex)
# 5) 对齐+重签名(uber-apk-signer 自动建 debug key,出 v1/v2/v3)
java -jar ~/.apklab/uber-apk-signer-1.3.0.jar --apks unsigned.apk --allowResign -o signed
# 6) 装机(签名不同,先卸原版)
adb uninstall com.join.android.app.mgsim.wufun
adb install -r signed/unsigned-aligned-debugSigned.apk
```

### 为什么能跑(不触发易盾)

- manifest 里壳组件**只有 MyApplication 一个**,换掉它壳就彻底不启动(无壳 provider/receiver)。
- 壳 so `libvuoum.so`(完整性校验/反调试核心)真实 dex **从不 loadLibrary** → 不加载 → 不校验 → 改字节也无所谓。
- `libovermind*.so`/`libpapa.so` 等是 app 真库,**全部保留**。

**结果**:启动 → 悟饭游戏厅隐私协议弹窗 → 点同意 → 游戏推荐主界面,`:mind`(Overmind VA)正常拉起,**稳定、无崩溃、无壳、无 frida**。

## 附:本机特有的 SELinux config.json 坑

KernelSU root 域 `u:r:ksu:s0` 在 `system_file` 标签的 `/data/local/tmp/re.zyg.fri/`:
- ✅ 能**覆盖已存在**文件、能 `rm`
- ❌ **不能 create 新文件、不能 relabel**;`setenforce` 被内核禁(旧手册的 `setenforce 0` 失效);bind-mount 被 KernelSU app-ns 隔离无效

**不碰 SELinux 的重建法 —— 硬链接**:
```bash
# 硬链接用 link/add_name 权限(ksu 有),非 create;新名字继承 system_file context
adb shell su -c "ln .../re.zyg.fri/libgadget32.so .../re.zyg.fri/config.json"
# cp 覆盖已存在文件 = O_TRUNC 不触发 create 检查(可以);不能用 '>' 重定向(带 O_CREAT 会被拒)
adb shell su -c "cp /data/local/tmp/cfg.json .../re.zyg.fri/config.json"
```
代价:覆盖 `libgadget32.so` 内容(32 位 gadget,arm64 用不到,无害)。
